# Scoped and transactional writes

Map three things together: required effects and durable replay; existing rows and multiplicities outside the write set; valid ignored conflicts, no-ops and internal row moves. Compare contract identities and typed values, not physical addresses. Keep every lookup within the authorized scope, including preservation queries, aggregates and receipts.

**Choose a boundary that holds by construction.** When code you do not control runs inside the operation (stored triggers, views, callbacks, plugins, user queries), an access boundary over that code is a boundary over an open language. Do not enforce it by rewriting, parsing or denylisting that language: each patch covers one spelling, equivalent forms bypass it, and rewrites break valid behavior. Prefer a layer where the property holds for every form: data the operation must not see is absent or unreachable while that code runs (engine-native policy, separate store or schema, transactional isolation, removed capability), and the result is checked against the expected effects before commit. Keep instrumentation of the open language as a last resort, validated against the native engine with valid and invalid controls.

**Prove the hardest boundary before the happy path.** Check the available runtime once. Build one small probe for the riskiest property and its valid control, choose the mechanism from that result, then implement and exercise that slice before expanding the suite. A passing transaction test alone does not establish the boundary. When the contract defines the outcome by reference to a trusted mechanism, for example the native engine on a copy that holds only the authorized rows, build that differential oracle as the first test and run every candidate mechanism against it; a mechanism that fails the oracle on a new case is replaced, not patched. If blocked, keep the working slice and record the exact gap.

Test isolation as noninterference: run the same request on states that differ only in protected data, including different values and absence, through every public interface. Outcomes, errors, receipts, counters and allocated identifiers must match, and protected rows must stay byte-identical. One matched output pair is not enough; inspect what the protected path can still read. Pair each protection with a valid tenant-local control and a genuinely failing control so it does not suppress legitimate behavior.

Before commit verify required effects and the absence of any other effect. Exercise the public interface, induce a storage failure after an earlier write to verify complete rollback, and check unchanged history and replay after reopening, malformed or differently typed out-of-scope data, and concurrency where required. Keep error assertions tied to the contract.

If two requirements or findings demand outcomes that cannot both hold, for example one needs an outcome that depends on data another forbids observing, demonstrate the conflict with a paired reproducer and ask for the policy decision. Do not patch toward both. Fresh review reruns the required checks and independently challenges the mechanism with a valid/invalid pair; repair and review the demonstrated delta within the same REWORK count.
