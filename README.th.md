# Lean Skills

[English](README.md) | **ภาษาไทย**

16 skills ที่ใช้แยกกันได้ ช่วยให้ coding agent วางแผน ลงมือทำ ทดสอบ และตรวจงาน
ติดตั้งทั้งชุดหรือแค่ตัวเดียวก็ได้ **ไม่ต้องมี Lean runtime หรือโฟลเดอร์ `.lean`**

ใช้กับ **Codex, Claude Code และ Antigravity** ผ่าน
[Skills CLI](https://github.com/vercel-labs/skills)
ถ้าต้องการคำอธิบายพร้อมแผนภาพ flow อ่านต่อที่ [คู่มือการใช้งาน](docs/guide.th.md)

## ทำอะไรได้

skill คือชุดคำสั่งให้ agent อ่านแล้วลงมือทำงานด้วยเครื่องมือของโปรเจกต์คุณเอง
ไม่มีอะไรทำงานอยู่เบื้องหลัง

แต่ละ skill รับผิดชอบ **งานเดียว** และจบที่ผลลัพธ์ที่ระบุไว้ เช่น scope ผลวินิจฉัย
ผล review หรือการเปลี่ยนแปลงที่ตรวจแล้ว คุณจึงติดตั้ง skill เดียวแล้วได้ผลงานครบในตัว
โดยไม่ต้องมีตัวอื่นประกอบ

[`lean-run`](skills/lean-run/SKILL.md) คือ **ทางเข้าหลัก** รับคำขอหนึ่งงานตั้งแต่การตัดสินใจ
ช่วงแรกจนส่งมอบพร้อมหลักฐาน และเรียก skill อื่นเฉพาะเมื่อช่วยให้งานดีขึ้น

## เริ่มต้นใช้งาน

เตรียม Node.js/npm (สำหรับ `npx`) และ coding agent ที่ใช้

### 1. ติดตั้ง

เลือกว่าจะให้ skills อยู่ที่ไหน:

- **ทุกโปรเจกต์** ใส่ `-g` ไฟล์ในโปรเจกต์จะไม่ถูกแก้
- **เฉพาะโปรเจกต์นี้** ไม่ใส่ `-g` และรันจากโฟลเดอร์หลักของโปรเจกต์

```sh
npx skills add aussadawut-dev/lean-skills -g --skill '*' -a codex claude-code antigravity -y
```

ถ้าต้องการแค่ตัวเดียว ให้ระบุชื่อ ตัวอย่างนี้ติดตั้ง `lean-review` ให้ Codex ในโปรเจกต์ปัจจุบัน:

```sh
npx skills add aussadawut-dev/lean-skills --skill lean-review -a codex -y
```

ปรับคำสั่งให้ตรงกับการใช้งาน:

- หลัง `-a` ใส่เฉพาะ agent ที่คุณใช้
- `--skill '*'` เลือกครบทั้ง 16 ตัว ต้องมีเครื่องหมายคำพูดรอบ `'*'`
- `-y` ข้ามคำถามยืนยัน ถ้าต้องการเลือก agent ผ่านเมนู ให้ตัดทั้ง `-a` และ `-y` ออก
- เพิ่ม `--list` เพื่อดูรายการ skills โดยยังไม่ติดตั้ง

การติดตั้งเฉพาะโปรเจกต์จะสร้างโฟลเดอร์และลิงก์ให้ agent พบ skills เช่น `.agents/skills/`
และ `.claude/skills/` รวมถึงข้อมูลการติดตั้งตามที่ host ใช้ ตรวจไฟล์ที่เพิ่มด้วย `git status`
แล้วเลือก commit เพื่อใช้ร่วมกับทีม หรือเพิ่มใน ignore rules หากใช้ส่วนตัว global skills เดิมไม่เปลี่ยน

### 2. เรียกใช้ skill

บอกชื่อ skill หรือใช้รูปแบบคำสั่งของ agent:

- **Codex:** `$lean-run เพิ่ม pagination และตรวจ flow การใช้งานจนจบ`
- **Claude Code:** `/lean-run เพิ่ม pagination และตรวจ flow การใช้งานจนจบ`
- **Agent อื่นที่รองรับ:** `ใช้ lean-run เพิ่ม pagination และตรวจ flow การใช้งานจนจบ`

agent เลือก skill จากคำอธิบายได้เองด้วย ไม่ต้องรัน `lean-init` ก่อน
และไม่ต้องติดตั้ง skill ตัวอื่นมาประกอบ

### 3. เสร็จแล้ว

ถ้ายังไม่พบ skill ที่เพิ่งติดตั้ง ให้โหลดใหม่หรือเริ่ม session ของ agent อีกครั้ง

## เลือก skill ให้เหมาะกับงาน

**รับผิดชอบงานทั้งหมด**

- **[lean-run](skills/lean-run/SKILL.md)**: รับผิดชอบงานตั้งแต่การตัดสินใจช่วงแรกจนส่งมอบพร้อมหลักฐาน

**ตัดสินใจว่าจะทำอะไร**

- **[lean-scope](skills/lean-scope/SKILL.md)**: ระบุว่างานครอบคลุมอะไรและจะตรวจรับอย่างไร
- **[lean-grill](skills/lean-grill/SKILL.md)**: หาจุดที่ยังไม่ชัดใน requirement หรือแผนก่อนเขียนโค้ด
- **[lean-research](skills/lean-research/SKILL.md)**: เปรียบเทียบแนวทาง พร้อมแหล่งอ้างอิงและข้อแลกเปลี่ยน

**ลงมือและตรวจงาน**

- **[lean-task](skills/lean-task/SKILL.md)**: วินิจฉัยบั๊ก หรือทำงานจนทดสอบและ review เสร็จ
- **[lean-agents](skills/lean-agents/SKILL.md)**: แบ่งงานให้ agent ที่มีอยู่ช่วยทำ
- **[lean-review](skills/lean-review/SKILL.md)**: ตรวจการเปลี่ยนแปลงเพื่อหาปัญหาและผลกระทบต่อของเดิม
- **[lean-gate](skills/lean-gate/SKILL.md)**: ตรวจหลักฐานก่อนสรุปว่างานเสร็จ
- **[lean-effort](skills/lean-effort/SKILL.md)**: กำหนดความละเอียดในการทำตามขั้นตอน

**งานเฉพาะทาง**

- **[lean-security](skills/lean-security/SKILL.md)**: ตรวจขอบเขตความปลอดภัยและยืนยันการแก้ไขที่ได้รับอนุญาต
- **[lean-release](skills/lean-release/SKILL.md)**: วางแผนหรือดำเนินการ release/recovery พร้อมตรวจผล
- **[lean-model-update](skills/lean-model-update/SKILL.md)**: ประเมินตัวเลือกโมเดลและเสนอปรับ configuration

**ตั้งค่าและดูแลชุด skills**

- **[lean-init](skills/lean-init/SKILL.md)**: ทำความเข้าใจคำสั่งและแนวทางทำงานของโปรเจกต์
- **[lean-instructions](skills/lean-instructions/SKILL.md)**: สร้างหรืออัปเดต `AGENTS.md` และ `CLAUDE.md` ที่ราก repository
- **[lean-target](skills/lean-target/SKILL.md)**: เลือกหรือ clone repository ของแอปอีกตัว
- **[lean-update](skills/lean-update/SKILL.md)**: อัปเดต Lean skills และเพิ่มตัวที่ขาด โดยรักษาส่วนที่คุณแก้เองไว้

## คำขอเดียว ตั้งแต่รับงานจนส่งมอบ

ใช้ `lean-run` เมื่อต้องการให้ agent รับผิดชอบงานทั้งหมด:

```text
ใช้ lean-run แก้ checkout ที่ตัดเงินแล้วไม่สร้าง order
เคลียร์ requirement สำคัญก่อน ทำให้เห็นบั๊ก แก้ไข
และตรวจ flow จนสร้าง order สำเร็จ ส่งมอบเป็น PR
```

skill จะเคลียร์การตัดสินใจสำคัญตั้งแต่ช่วงแรก แล้วทำงานที่ได้รับอนุญาตต่อจน implementation
ตรวจการทำงานร่วมกันของระบบ review และส่งมอบ โดยคุณไม่ต้องเรียก skill ถัดไปเอง
หากพบข้อเท็จจริงใหม่ที่กระทบการตัดสินใจสำคัญ agent ยังอาจต้องถามคุณ

ข้อตกลงที่ agent ใช้ทำงานเรียกว่า **contract** คุณเพิ่มหรือแก้ข้อกำหนดได้ตลอด
`Recap:` ครั้งถัดไปจะแสดง contract ล่าสุด พร้อมงานเดิมที่ยังค้างและงานที่ตรวจผ่านแล้ว
agent ทำงานต่อจาก contract นี้และใช้ตรวจอีกครั้งตอนส่งมอบ

การส่งมอบหมายถึงสิ่งที่คุณขอ ถ้าไม่ระบุปลายทาง จะหมายถึงการเปลี่ยนแปลงที่ตรวจแล้วใน
workspace ปัจจุบัน การเปิด PR หรือ deploy ต้องมีคำสั่งอนุญาตและสิทธิ์เข้าถึงที่ตรงกัน

`lean-run` ทำขั้นตอนหลักเองได้เมื่อติดตั้งเดี่ยว ส่วน [`lean-task`](skills/lean-task/SKILL.md)
คือขั้นตอน implementation เดียวกันที่ใช้แยกได้ เลือกใช้เมื่อต้องการขั้นตอนนั้นโดยตรง
ระหว่างขั้นตอน ตัวควบคุมเก็บการตัดสินใจและจำนวนรอบแก้ไขไว้ ไม่สำรวจโปรเจกต์ซ้ำ
และหยุดการลองซ้ำที่ไม่คืบหน้า

### งานกว้างจะกลายเป็นรอบคำถาม

เมื่องานยังกว้างหรือไม่ชัด `lean-run`, `lean-task` และ `lean-scope` จะสำรวจ goal ก่อนสรุป
scope ด้วยตัวอย่าง use case ตัวเลือกขนาดงาน และคำถามชุดเล็ก

- คำถามมีเลขข้อ ตัวเลือกเป็นตัวอักษร และมีคำตอบแนะนำ เช่น `1a 2b` เมื่อเหมาะสม
  คุณตอบด้วยคำของตัวเองได้เช่นกัน
- การเว้นข้อไว้ไม่ถือว่ายอมรับคำแนะนำ
- ก่อนปิด scope agent จะถามว่ายังขาดอะไร และสำรวจสิ่งที่เพิ่มเข้ามา
- งานเล็ก งานที่ชัด หรือคำสั่งให้ลุยเลย จะข้ามรอบที่ไม่จำเป็น แต่การตัดสินใจที่งานขาดไม่ได้
  ยังต้องรอคำตอบจากคุณ

เมื่อ host และโหมดปัจจุบันรองรับ agent จะใช้หน้าต่างคำถามแบบมีตัวเลือก แต่ละคำถามมีบริบทพอ
และพิมพ์แก้เพิ่มเติมได้ ตัวเลือกที่เลือกไว้ล่วงหน้ายังต้องกดส่ง หากไม่รองรับจะถามในแชทแบบเลขข้อ
พร้อมข้อความตอบที่คัดลอกได้ ส่วนการเติมข้อความในช่องแชทให้ล่วงหน้าขึ้นอยู่กับ host

### โหมด Auto และ Manual

ตามค่าเริ่มต้น agent เลือก `lean-run` เองเมื่อเหมาะกับงาน ถ้าต้องการให้เป็นค่าเริ่มต้นของ
**งาน implementation ทุกงานที่ต้องทำจนส่งมอบ** ให้เปิดการเรียกอัตโนมัติไว้ และเพิ่มกฎนี้ใน
`AGENTS.md` ของโปรเจกต์ (Codex) หรือ `CLAUDE.md` (Claude Code):

```text
เรียก lean-run เมื่อเริ่มงาน implementation ใหม่ที่ต้องทำจนส่งมอบทุกครั้ง
เมื่อมีข้อกำหนดเพิ่ม ให้รวมเข้ากับ run ที่กำลังทำอยู่
```

ถ้าต้องการโหมด **Manual** ให้เอากฎด้านบนออก แล้วตั้งค่า skill ที่ติดตั้งไว้:

- **Codex:** ตั้ง `policy.allow_implicit_invocation: false` ใน `agents/openai.yaml` ของ skill
  แล้วเริ่มงานด้วย `$lean-run …`
- **Claude Code:** เพิ่ม `"skillOverrides": {"lean-run": "user-invocable-only"}` โดยรวมกับค่าเดิมใน
  `.claude/settings.local.json` ของโปรเจกต์ แล้วเริ่มงานด้วย `/lean-run …`
  ดู [การตั้งค่า skill ใน Claude Code](https://code.claude.com/docs/en/skills#override-skill-visibility-from-settings)

เมื่อต้องการกลับไปใช้ Auto ให้ตั้งค่าของ Codex เป็น `true` หรือลบ override ใน Claude Code
แล้วเพิ่มกฎของโปรเจกต์อีกครั้ง ถ้า host ไม่มีตัวตั้งค่า ให้ระบุโหมดที่เลือกในคำสั่งของโปรเจกต์
เริ่ม session ใหม่เพื่อตรวจว่าโหมดถูกต้อง

## ผลลัพธ์จบอย่างไร

ทุก skill ระบุข้อมูลตั้งต้น จุดสิ้นสุด หลักฐาน และสิ่งที่ต้องทำเมื่อทำไม่จบ
งานสำรวจ วินิจฉัย กำหนด scope review หรือส่งต่องาน ถือเป็นผลงานที่ครบในตัว
และไม่อ้างว่ามี implementation หรือ release ที่คุณไม่ได้ขอ

ผลลัพธ์ระบุสิ่งที่ตรวจ (เนื้อหาหรือสภาพแวดล้อม) สิ่งที่พบ ข้อจำกัด และขั้นตอนถัดไป
แล้วจบด้วย **สถานะ** หนึ่งตัว:

- **`READY`**: แผนชัดแล้ว หรืออยู่บนสมมติฐานที่ระบุไว้และย้อนกลับได้
- **`PASS`** / **`REWORK`**: ผลตัดสินของ review
- **`DONE`**: งานที่ได้รับอนุญาตเสร็จแล้ว พร้อมหลักฐานปัจจุบันครบทุกเงื่อนไขบังคับ
- **`BLOCKED`**: ขาดสิ่งจำเป็น และผลลัพธ์ระบุว่าขาดอะไร
- **`FAILED`**: มีความล้มเหลวที่ยืนยันแล้วและยังไม่ได้แก้

สถานะผูกกับขอบเขตที่รายงาน ไม่ใช่ทั้งโปรเจกต์ หาก release ล้มเหลวแต่ rollback สำเร็จ
จะรายงานทั้งสองผล ส่วนที่จำลองระบบภายนอกและขอบเขตที่ยังไม่ได้ทดสอบต้องเปิดเผยเสมอ
`DONE` จึงไม่ใช่การรับประกันว่าทุกงานจะสำเร็จ

บาง skill มีโหมดเพิ่มที่โหลดเฉพาะเมื่อจำเป็น ได้แก่ การวินิจฉัยต้นเหตุใน `lean-task`,
acceptance ด้านผลิตภัณฑ์และ accessibility ใน `lean-scope`, การตรวจ UI ตามงานใน implementation
และ review และการทำต่อข้าม session ใน `lean-run` และ `lean-agents`
เอกสาร references ของแต่ละโหมดอยู่ในแพ็กเกจของ skill นั้นเอง ไม่ต้องติดตั้งตัวอื่น

**การส่งต่องาน (handoff)** บันทึกการตัดสินใจ สถานะงานที่แน่นอน ความสดของหลักฐาน
งานที่ยังรอผล และจำนวนรอบแก้ไข การบันทึก checkpoint ถาวรทำเมื่อคุณขอ
หรือเมื่อโปรเจกต์มีบันทึกแบบนั้นอยู่แล้ว

### งานเฉพาะทางเป็นทางเลือก

[`lean-security`](skills/lean-security/SKILL.md) ตรวจความปลอดภัยในขอบเขตที่กำหนด หรือแก้ไขตามสิทธิ์
ที่ได้รับ ข้อพบต้องมีหลักฐานที่ไล่ตามได้
[`lean-release`](skills/lean-release/SKILL.md) วางแผนหรือดำเนินการ release/recovery ต้องยืนยัน
artifact ที่แน่นอน สุขภาพของระบบเป้าหมาย และการตรวจ migration/recovery ที่เกี่ยวข้อง
ทั้งสองตัวไม่ใช่ขั้นตอนบังคับของทุกงาน

งานตัดสินใจด้าน performance ใช้ [`lean-research`](skills/lean-research/SKILL.md) โดยกำหนด workload
และวัด baseline เมื่อได้รับอนุญาตให้ทดลอง ไม่มี skill ใดเริ่ม benchmark เอง

## แบ่งงานให้โมเดลอื่น

เมื่อได้รับอนุญาตและการแบ่งงานช่วยได้จริง ตัวควบคุมจะเลือก model และ reasoning effort
ให้แต่ละงานจากความสามารถที่ provider ปัจจุบันยืนยันแล้ว ตัวเลือกที่คุณระบุและ mapping
ของโปรเจกต์มาก่อนเสมอ

- งานแก้เชิงกลไก งาน implementation และงาน review ซับซ้อน ต้องการความสามารถต่างกัน
  จึงไม่มีสเกลขนาดเดียวที่ใช้ข้าม provider
- งานเล็กทำใน agent หลักได้ โดยปริยายใช้ worker ไม่เกินหนึ่งตัว เว้นแต่คุณขอให้ทำงานขนาน
- ความละเอียดของขั้นตอน ([`lean-effort`](skills/lean-effort/SKILL.md)) แยกจาก reasoning effort ของโมเดล

ชื่อ worker ใช้รูปแบบ `<taskname> - <model name>|<effort>` เช่น
`api_builder - gpt-6.1-sol|medium` ชื่อถูกส่งเป็นข้อความ literal เสมอ `|` จึงไม่กลายเป็น shell pipeline

- **Claude Code** ใช้คำอธิบายงานของ Agent หรือ `--name` สำหรับ session CLI ที่เปิดแยก
- **Antigravity** ใช้ Role ของ subagent
- **Host ที่จำกัดรูปแบบ ID ภายใน** แสดงชื่อเต็มในข้อความมอบหมายงานและรายงาน คู่กับ runtime ID
  ส่วน UI ที่ไม่มีช่องตั้งชื่อแสดงผลจะใช้ชื่อของตัวเอง

ชนิด agent และ instance ID ที่ได้กลับมาแยกจากชื่อนี้

รายงานแยกค่าที่ขอออกจากค่าที่ runtime ส่งกลับจริง และบอกตรง ๆ เมื่อไม่มีตัวควบคุมหรือ metadata
การแบ่งงานไม่เปลี่ยน provider ไม่ใช้ paid API สำรอง และไม่แก้ configuration ของโมเดลเอง

## สิ่งที่ยังอยู่ในมือคุณ

skills ให้คำสั่งกับ agent เท่านั้น ไม่มีบริการเบื้องหลัง hooks อัตโนมัติ ระบบควบคุมสิทธิ์
หรือหลักฐาน review ที่มีลายเซ็นรับรอง การตรวจและ review ทำผ่าน agent ด้วยเครื่องมือและกติกา
ของโปรเจกต์คุณ

- **สิทธิ์** การติดตั้ง skill ไม่ได้ให้สิทธิ์ commit, push, deploy, ใช้ API ที่เสียเงิน
  หรือเปลี่ยนสิทธิ์ของผู้ให้บริการ คำสั่งของคุณและกติกาของโปรเจกต์เป็นตัวตัดสิน
- **ความจำ** ค่าที่ตั้งและ repository ที่เลือกอยู่ในบทสนทนา เว้นแต่คุณขอให้บันทึกไว้
- **ความสามารถ** การแบ่งงานต้องมีเครื่องมือเรียก agent การประเมินโมเดลต้องมีโจทย์ เครื่องมือ
  และสิทธิ์ที่เหมาะสม ชุดนี้ไม่มีทะเบียนโมเดล ชุด benchmark หรือระบบคิวงาน
  agent จะรายงานความสามารถที่ขาดแทนการทำเหมือนว่ามีอยู่

## สัญญาณว่าใช้ได้ผล

- การตัดสินใจที่งานต้องใช้มาถึงคุณตั้งแต่ต้น เป็นคำถามมีเลขข้อไม่กี่รอบ ไม่ใช่ทีละข้อตลอดงาน
- `Recap:` แต่ละครั้งแสดง contract รวมทั้งสิ่งที่ยังค้างและสิ่งที่ตรวจแล้ว
- รายงานสุดท้ายระบุหลักฐาน และจบด้วยสถานะหนึ่งตัวตามขอบเขตที่คุณขอ
- ผล `BLOCKED` หรือ `FAILED` บอกชัดว่าขาดอะไรหรืออะไรพัง

## คำถามที่พบบ่อย

**ต้องติดตั้งทุก skill ไหม**
ไม่ต้อง ทุก skill ใช้เดี่ยวได้ และ `lean-run` ทำขั้นตอนหลักได้โดยไม่มีตัวอื่น

**มี skills ชื่อ `lean-*` อยู่แล้ว ติดตั้งแล้วจะทับไหม**
ทับชื่อเดียวกัน ให้เก็บส่วนที่แก้เองไว้ก่อน หรือใช้ [`lean-update`](skills/lean-update/SKILL.md)
skills ในโปรเจกต์ยังมีผลต่อเวอร์ชันที่ agent พบด้วย

**ติดตั้งแล้วแต่ไม่เห็น skill**
โหลดใหม่หรือเริ่ม session ของ agent อีกครั้ง แล้วตรวจว่ามีสำเนาในโปรเจกต์บังตัวที่ติดตั้งไว้หรือไม่

**`lean-run` รับประกันว่างานสำเร็จไหม**
ไม่ `DONE` ต้องมีหลักฐานปัจจุบันครบทุกเงื่อนไขบังคับ ถ้าไม่ครบจะได้ `BLOCKED` พร้อมสิ่งที่ขาด
หรือ `FAILED` พร้อมความล้มเหลวที่ยังไม่แก้

**ทดสอบกับ host ไหนแล้วบ้าง**
ดู[หลักฐานการทดสอบ](#หลักฐานการทดสอบ) Codex ผ่านชุดสถานการณ์เต็ม ส่วน Claude Code และ Antigravity
มีเฉพาะการทดสอบชื่อ subagent จริง

## สำหรับผู้ร่วมพัฒนา

clone repository นี้ แล้วติดตั้งจากโฟลเดอร์หลักเพื่อลอง skills ที่แก้ในเครื่อง:

```sh
npx skills add ./ --skill '*' -a codex claude-code antigravity -y
```

ตรวจงานด้วย Python และ Node.js/npm โดย CI รันทั้งสองคำสั่ง:

```sh
python3 -m unittest discover -s tests -v
python3 tests/install_smoke.py
```

- **Unit tests** ใช้เฉพาะ standard library ของ Python
- **Smoke test** ใช้ `skills@1.7.4` ผ่าน `npx` จึงต้องเข้าถึง registry ได้หรือมีแพ็กเกจใน cache
  ทดสอบติดตั้งครบชุดและติดตั้งทีละตัวทั้ง 16 ตัว ทั้งแบบ global และเฉพาะโปรเจกต์ รวม **34 กรณี**
  ในโฟลเดอร์ผู้ใช้และโปรเจกต์จำลอง ตรวจไฟล์ references ทั้งหมดในแพ็กเกจ ไม่ใช่แค่ `SKILL.md`
  และ `LICENSE` และตรวจการแยกขอบเขตโดยไม่แก้ global skills จริงและไม่เรียก LLM
  ถ้ามี CLI อยู่แล้วจะรันแบบ offline ได้: `python3 tests/install_smoke.py --cli /path/to/skills/bin/cli.mjs`

การทดสอบนี้ยืนยันแพ็กเกจและการติดตั้ง ไม่ได้ยืนยันพฤติกรรมของ agent ถ้าต้องการตรวจพฤติกรรม
ให้ใช้[กรณีประเมินพฤติกรรม](docs/evaluation.md) ทดลองกับ agent ในพื้นที่แยก และบันทึก host,
model, ผลงาน และผลตรวจที่เกิดขึ้นจริง การไล่อ่านสถานการณ์ไม่นับเป็นการทดลองจริง
และไม่ใช่หลักฐานว่าใช้ได้เท่ากันทุก agent

เมื่อแก้คู่มือ ให้ปรับภาษาอังกฤษและภาษาไทยให้ตรงกัน ไฟล์ skill ยังคงเป็นภาษาอังกฤษ
เขียน release note ตาม [template](.github/release-template.md)
